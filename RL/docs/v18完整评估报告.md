## 一、先说结论

**v18 是一次「修好一半、暴露更深问题」的实验。**

| 组件 | 状态 | 核心数据 |
|---|---|---|
| P1 纯翻转 | 🟡 可用但未达预期 | 训练环境 63.0%（v16 是 97.5%）；翻转耗时 0.105s（21 步） |
| P2 高速刹停 | ❌ 完全未学会 | 0%；姿态达标 0 步、角速度达标 16 步 |
| 联合 | ❌ 无法运行 | 交接 ω 中位 42 rad/s，远超 P2 的 26 上限 |

**最关键的发现：P1 与 P2 的分布再次错配，而且方向反了。**

## 二、v18 完整奖励函数（你要看的）

### Phase 1（纯翻转）

```python
# 总奖励 = 4 项相加
reward = r_up + r_effective_rot + r_bonus + 0.5

# 各项定义：
r_up            = -3.0 * (1.0 - up_z)          # 姿态：倒扣罚 -6，正立 0
r_effective_rot = 0.08 * min(Δup_z/dt, 3.0)     # 有效旋转：朝翻正方向转才给（上限 +0.24）
r_bonus         = 1.0 if up_z > 0.9 else 0.0   # 里程碑
存活常数         = +0.5                          # 每步白给

# 终止条件（关键）：
if up_z > 0.7:
    reward += 20.0       # 交接奖励
    terminated = True    # 翻正即结束，不看 ω、不看 vxy
```

**设计哲学**：P1 只管"把机身翻正"，速度（旋转/平移）全部交给 P2。
不罚高度、不罚水平速度、不罚角速度 —— 这些都是翻转的合理代价。

### Phase 2（高速刹停）

```python
# 总奖励 = 7 项相加
reward = (r_up + r_rate_stab + r_bonus + r_vxy_stab + r_vz_stab + r_act + 0.5)

r_up         = -3.0 * (1.0 - up_z)                        # 姿态
r_rate_stab  = -(0.5*ω + 0.02*ω²)                         # 角速度（v18 改混合项）
r_bonus      = 1.0 if up_z > 0.9 else 0.0                 # 里程碑
r_vxy_stab   = -1.0 * sqrt(vx² + vy²)                     # 水平速度
r_vz_stab    = -0.6 * |vz|                                # 垂直速度（目标悬停 0）
r_act        = -0.03 * Σ(a - a_last)²                     # 动作平滑
存活常数      = +0.5

# 终止条件：
if up_z>0.98 且 |vz|<0.5 且 ω<1.0，连续 50 步:
    reward += 20.0
    terminated = True
```

### v18 相对 v17 的三处改动

| 项 | v17 | v18 | 意图 | 实际效果 |
|---|---|---|---|---|
| P1 ω 采样 | 每轴 2~12（模长 max 18.3） | **模长 2~26** | 覆盖端到端真实开局 | ⚠️ 见第四节 |
| P2 `r_rate_stab` | `-0.08ω²` | **`-(0.5ω+0.02ω²)`** | 修低区梯度塌陷 | ✅ 角速度达标 0→16 步 |
| P2 `r_vz_stab` | `-1.5\|vz\|` | **`-0.6\|vz\|`** | 让旋转项主导 | ⚠️ 姿态项反被压垮 |

## 五、根因分析

### 根因 1：P1 交接的 ω 远超 P2 训练上限（最致命）

```
P1 实际交接 ω：中位 42、P90 52、max 59.6
P2 训练分布  ：模长 1~26
差距         ：中位就超了 1.6 倍，P90 超 2 倍
```

**为什么之前测出"交接 ω 中位 14.3"？**
那次是在**端到端环境（phase=0）**测的，P1 在其中行为不同。
本次是在 **Phase 1 训练环境**测的 —— 这才是 P1 真实训练出的行为，
也是分阶段部署时真正会发生的交接。

> **元规则：交接分布必须在「P1 自己的训练环境」里测，不能用端到端环境代替。**

### 根因 2：P1 的 +20 交接奖励诱导"翻得越猛越好"

P1 奖励里 `up_z>0.7 即 +20 终止`，且**不罚角速度**。
策略的最优解是"用最大力矩猛翻到 0.7"，此时 ω 自然极大（42 rad/s）。
这不是 bug，是奖励设计的必然结果。

### 根因 3：姿态项与速度项量纲不对等（P2 姿态失效的原因）

| 量 | 值域 | 满幅惩罚 |
|---|---|---|
| 姿态 `up_z` | [-1, 1]（有界） | `-3×(1-up_z)` = **-3** |
| 垂直速度 `vz` | [-6, +2]（无界） | `-0.6×6` = **-3.6** |

姿态崩到 66°（up_z=0.4）只罚 -1.8，而下坠 5 m/s 罚 -3.0 —— 姿态项被压过。

## 六、v18 的收获（不能只看失败）

1. **P1 翻转速度提升**：0.110s → 0.105s（21 步），依然保持"翻正极快"的优势
2. **P2 角速度项修复有效**：达标步数 0 → 16，混合项方向正确
3. **发现交接分布必须在 P1 训练环境测** —— 这是重要的方法论修正
4. **物理稳定性守卫**已加入（ω>60 判定失控），此前多轮数据被 NaN 污染

## 七、v19 拟案（三个改动，都有数据支撑）

| # | 问题 | 改法 | 依据 |
|---|---|---|---|
| 1 | 交接 ω 42 vs P2 上限 26 | P2 训练 ω 上限 26 → **60** | 必须覆盖 P1 真实输出（max 59.6） |
| 2 | P2 姿态项被压过 | 姿态改门槛式：`up_z<0.85` 时 `-12×(0.85-up_z)/0.85` | 账本已验证：up=0.4 时罚 -6.35 |
| 3 | P1 训练不充分 | 训练步数 200万 → **350万** | ω 覆盖 +42% 但预算没加 |

**同时要改的评估流程**：
- 交接分布统一用 `eval_phase.py`（在 P1 训练环境测）
- 每轮必做「P2 判据可达性检查」（PD 基线 ≥8/10）
