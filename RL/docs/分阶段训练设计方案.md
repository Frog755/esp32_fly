## 一、为什么需要分阶段

### 问题：一个网络无法同时胜任两种矛盾的控制风格

实测证据（v10 Tanh 实验发现）：

| 状态 | 策略实际输出 | 这是对的吗 |
|---|---|---|
| 倒扣中（up_z < 0.3） | 大幅动作，54.6% 时间贴 ±0.9 饱和 | ✅ **对** —— 最大力矩才最快翻正 |
| 回正后（up_z > 0.9） | 同样倾向大幅动作 | ❌ **错** —— 此时应精细微调 |

关键洞察（mj 提出）：
> **倒扣时激进猛转本来就是对的；精细调整应该是在基本回正之后才做的。**

所以这不是"输出层饱和"的缺陷，而是**一个网络被要求同时胜任两种截然
不同的控制风格**——这才是真正的病根。

### 结论
需要按姿态分区，训练两个策略：
- 策略 A 只负责"从倒扣翻正"（猛、快、不心疼）
- 策略 B 只负责"从翻正到稳定"（稳、准、细腻）

## 二、两阶段定义

### Phase 1：翻转阶段（Recovery Policy）

| 项 | 定义 |
|---|---|
| **触发区间** | `up_z < 0.5`（约 tilt > 60°） |
| **初始状态采样** | 只在此区间随机采样初始姿态（含 180° 全倒扣） |
| **目标** | 尽快把 `up_z` 推到 0.7 以上 |
| **奖励设计重点** | 姿态改善（`r_up`）+ 有效旋转（`r_effective_rot`）；**不罚**高度、不罚水平速度、不罚角速度 |
| **终止条件** | `up_z > 0.7`（成功交接） 或 坠地 / 超时 |
| **动作风格** | 允许饱和，允许大角速度 |

### Phase 2：稳定阶段（Stabilize Policy）

| 项 | 定义 |
|---|---|
| **触发区间** | `0.7 ≤ up_z < 1.0`（或 `up_z > 0.5` 但未稳定） |
| **初始状态采样** | 在 `up_z ∈ [0.7, 0.95]` 随机，带一定下坠速度与角速度 |
| **目标** | 把姿态稳定到 `up_z > 0.98` 且 `|vz| < 0.5` 且 `|ω| < 1.0` |
| **奖励设计重点** | 抗饱和：奖励小动作、奖励平滑；强罚角速度、强罚 vz 偏差 |
| **终止条件** | 稳定达标 或 坠地 / 超时 |
| **动作风格** | 必须精细，不允许长期饱和 |

## 三、部署时的切换逻辑（关键）

mj 的理解是"两个命令分别执行"——**训练阶段对，部署阶段不对**。

- **训练阶段**：确实是两次独立训练（两个命令，两个模型文件）
- **部署阶段**：两个模型都烧进 ESP32，飞控代码根据当前 `up_z` 选择调用哪个

```c
// 部署时的伪代码（ESP32 端）
float up_z = 1.0f - 2.0f * (q[1]*q[1] + q[2]*q[2]);

if (up_z < 0.5f) {
    // 倒扣区：调用 Phase 1 网络（翻转）
    recovery_policy_forward(obs, act);
} else if (up_z < 0.95f) {
    // 过渡区：调用 Phase 2 网络（稳定）
    stabilize_policy_forward(obs, act);
} else {
    // 已稳定：切回传统 PID 悬停控制
    pid_hover_controller(obs, act);
}
```

**滞回（hysteresis）**：为避免在阈值附近抖动，切换要加滞回：
- Phase 1 → 2：`up_z > 0.7` 才切
- Phase 2 → 1：`up_z < 0.5` 才切回
- 中间 0.5~0.7 保持当前阶段不变

## 五、风险与对策

| 风险 | 说明 | 对策 |
|---|---|---|
| **切换点难调** | Phase 1→2 切换太早会"翻不完就交给稳定器"，太晚会撞地 | 先做参数扫描，用联合评估确定最优阈值 |
| **分布偏移** | Phase 1 训练时没见过 Phase 2 的输出，交接时状态可能不连续 | 在 Phase 2 训练时混入一些 Phase 1 末期的真实状态 |
| **可能掩盖真实问题** | 分层能让系统表现变好，但会模糊"是策略学会了还是状态机救的" | 同时保留端到端方案作为对照 |
| **调试复杂度翻倍** | 两个模型都要调，且要联合调试 | 先各自达标，再做联合调试 |

## 八、给 mj 的决策点

1. **是否现在就开始实现？**
   - 建议：等 v11 结果出来再决定。如果 v11 大幅提升，说明容量假设成立，
     分阶段的优先级可降低；如果 v11 也失败，说明结构问题更根本，分阶段价值更高。

2. **Phase 2 是否考虑直接用 PID 而非 RL？**
   - 这是一个务实选项：Phase 1 用 RL（因为倒扣翻转确实难），
     Phase 2 用 PID（因为稳定控制是 PID 的强项）。
   - 好处：工作量减半，且 PID 在稳定控制上比 RL 更可靠。
   - 坏处：面试叙事弱一些（"只用 RL 解决最难的部分"也说得通）。

3. **是否保留端到端方案作为对照？**
   - 强烈建议保留。有对照组才能证明分层方案的增益。
