## 二、三条路线的总结论

### 路线 A：端到端奖励迭代（6 轮）
- **最佳**：E-A2 = 61.1 / 56.5 / 44.2 / 27.7%
- **有效改动**：姿态项变号（+50pp）、r_vxy 按姿态分档（+6pp）、有效旋转奖励（+7pp）
- **关键教训**：辅助奖励量级必须 < 主奖励的 5%（E-A 用 0.8 崩盘，0.08 最优）

### 路线 B：网络结构改造（3 轮，全败）
| 改动 | 结果 | 根因 |
|---|---|---|
| History Stacking 43维 | 7.8% | 信息变多但网络没变宽 |
| Tanh 输出压缩 | 0.2% | 饱和区梯度消失 |
| 加宽 [128,128] | 54.3% | 过参数化，样本效率下降 |

**结论：网络结构层面无优化空间，瓶颈在任务定义。**

### 路线 C：分阶段训练（6 轮，进行中）
- **P1 纯翻转**：训练环境 97.5%，端到端环境 98%/78%/60%（分布错配）
- **联合最佳**：v15b = 63.1 / 50.9 / 38.5 / 24.3%（仅 d=0.3 反超端到端 2pp）
- **分阶段的真实优势**：翻转耗时 0.10~0.14s（端到端 0.94s，快 7 倍）

## 三、踩过的坑与元规则（最有价值的部分）

### 1. 奖励量级必须算账本
| 事故 | 现象 | 根因 |
|---|---|---|
| v4 | 成功率反降 8pp | 全局惩罚误伤「翻转必然伴随的水平速度」 |
| E-A | 61% → 2.3% | 辅助奖励 +6.4 与主奖励 -6.0 同级，策略刷分 |
| E-A3 | 61% → 2.0% | 系数 0.08→0.16 就跨过相变点，悬崖式崩盘 |
| v17 | P2 永远 0% | ω² 低区梯度塌陷 36 倍，被 vz 项压制 |

> **元规则**：新增奖励项前，必须列出「典型状态下各项数值」，确认量级比例合理。
> 辅助项上限 ≈ 主惩罚项的 5%，且优先用**线性 + 小平方混合**避免低区梯度塌陷。

### 2. 惩罚必须问「何时生效」
- v5 的 `r_vxy` 只在 `up_z>0.7` 生效（翻转时不管水平速度）→ 有效
- v4 的 `r_vxy` 全局生效 → 误伤翻转 → 失败

### 3. 终止条件会塑造策略盲区
- v13 的「达标即终止 +2」成了逃逸出口 → 策略学会冲过终点线而非停在终点线
- v12 的「up_z>0.7 即终止」→ P1 不学刹车 → 交接甩出 26 rad/s

> **元规则**：任何「达标即终止」的设计，都要问达标瞬间的**状态导数**（角速度、速度）是否也被约束。

### 4. 训练分布必须匹配部署分布
| 事故 | 数据 | 后果 |
|---|---|---|
| P1 ω 只采 2~12（模长 max 18.3） | 端到端 d=1.0 真实 max 24.7 | 45.7% 开局超经验 → 翻正率仅 60% |

> **元规则**：先实测下游/部署环境的状态分布，再定上游训练采样范围，**不要拍脑袋加裕量**。

### 5. 观测与奖励必须表达一致
- v17 的 `descend_rate` 同时出现在奖励和观测第 19 维
- 只改奖励不改观测 → 策略收到矛盾信号（奖励说悬停、观测说缓降）

> **元规则**：改任务目标时，检查该目标是否同时出现在观测里。

### 6. 判据可达性必须先验证
| 版本 | 判据 | PD 达标率 | RL 结果 |
|---|---|---|---|
| v14 | 加 vxy<0.5 | 2/10 | 0%（不可达） |
| v15 | 改 vxy<1.0 | 6/10 | 0%（仍偏难） |
| v17 | 回退到 v13 版 | 10/10 | 0~3%（可达，卡在别处） |

> **元规则**：新判据先用 PD 基线测，**≥8/10 才让 RL 跑**。代价 30 秒，省 35 分钟废训练。

### 7. 训练指标 vs 正式评估的判据差异
- `train_ppo.evaluate_policy`（宽松）：曾翻正 + 未坠地
- `eval.py`（严格）：活满全程 + 状态收敛
- **实测差 7 倍**（v8 的 28% vs 2.9%）

> **元规则**：训练内曲线只能看趋势，**所有跨实验结论必须用 eval.py**。

### 8. 基础设施 bug 会污染所有结论
- 物理仿真在 ω>200 时数值爆炸（NaN），导致联合评估出现「交接 ω=784 rad/s」这类荒谬数字
- 修复：加物理稳定性守卫（ω>60 判定失控终止）

> **元规则**：出现物理上不可能的数字时，先怀疑仿真器，不要急着改策略。

## 六、如何复现任意一轮

```bash
cd /home/frog/embodied_ai/esp32_fly/RL
source /home/frog/ai_workspace/deepseek_workspace/esp32-rl-无人机回正/.venv/bin/activate

# 1. 端到端训练（以 E-A2 配置为例）
#    需先把 env 的奖励恢复为 E-A2 版本（见实验日志第 7 轮）
python3 train_ppo.py --mode curriculum --start 0.2 --steps 1000000 \
    --net mlp --seed 42 --out models/run_name --tag run_name

# 2. 分阶段训练
python3 train_ppo.py --mode hard --difficulty 1.0 --phase 1 \
    --steps 2000000 --out models/p1_xxx --tag p1_xxx
python3 train_ppo.py --mode hard --difficulty 1.0 --phase 2 \
    --steps 2000000 --out models/p2_xxx --tag p2_xxx

# 3. 评估（统一 1000 回合）
python3 eval.py --model models/xxx/model.zip --out results/xxx

# 4. 分层联合评估
python3 eval_hierarchical.py --phase1 models/p1_xxx/model.zip \
    --phase2 models/p2_xxx/model.zip --episodes 1000

# 5. 对比两个 run
python3 report.py --runs run_a run_b
```
