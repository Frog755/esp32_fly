# v19 诊断报告：P2 恒 0% 的真因（奖励倒挂）

> 日期：2026-11-04
> 一句话结论：**P2 三轮 0% 不是「交接 ω 分布不匹配」，而是「达标即终止」造成的奖励倒挂 —— 不及格比满分多赚 3.6 倍。**
> 这份报告同时纠正了本人在 v16~v18 期间的三次误诊。

---

## 0. 一切从一个数字开始

mj 的问题：「我最终只需要他能稳定姿态朝上……yaw 角速度怎么转都无所谓，
但如果有 z 轴角速度肯定不行。能不能降低难度？或者 P1 推出的姿态条件给宽松一点，
给 P2 更多时间去减速稳定姿态？」

为了回答这个问题，我先去量「交接瞬间 ω 里有多少是不改变倾角的分量」。
量完之后，所有东西都变了。

---

## 1. 实测数据（全部为脚本产出，非推断）

### 1.1 交接 ω 的分量分解

脚本：`scripts/diagnose_handoff_split.py`，数据：`results/handoff_split.json`
模型：`models/p1_v18/model.zip`（phase=1 环境，300 回合，188 个成功交接）

| 量 | 中位 | 均值 | P90 | max |
|---|---|---|---|---|
| \|ω\| 总模长 | 42.69 | 41.52 | 52.93 | 59.48 |
| \|ω_tilt\| = √(wx²+wy²) | 42.53 | 41.14 | 52.60 | 59.29 |
| \|ω_yaw\| = \|wz\| | 3.09 | 4.16 | 9.77 | 16.65 |
| yaw 能量占比 | **0.5%** | 2.0% | 5.9% | 22.0% |

**结论：mj 的提议①（yaw 无所谓，放宽自旋）无效。**
自旋只占总角速度能量的 0.5%，`ω_tilt` 42.53 对 `|ω|` 42.69 几乎没有差别。
放宽 yaw 不会降低任何难度，因为本来就没有 yaw 污染。

## 2. 真因：达标即终止导致的奖励倒挂

### 2.1 原始代码（v16~v18，共三轮）

```python
stable_now = (up_z > 0.98 and abs(vz) < 0.5 and omega_norm < 1.0)
self._stable_steps = self._stable_steps + 1 if stable_now else 0
if self._stable_steps >= 50:
    reward += 20.0
    terminated = True          # ← 病灶在这里
```

### 2.2 回报账本（800 步回合，实测非估算）

| 策略 | 推力/重力 | 存活步 | 最长达标 | 累计回报 |
|---|---|---|---|---|
| 恒定 u=0.50 | 0.50 | 219 | 13 | **10.3** |
| 恒定 u=0.60 | 0.72 | 299 | 17 | **132.0** |
| 恒定 u=0.65（永远差一点） | 0.84 | 414 | 25 | **304.9** |
| 恒定 u=0.70（**完全达标**） | 0.98 | 50（达标即终止） | 50 | **84.2** |
| 恒定 u=0.7075（悬停，**完全达标**） | 1.00 | 50（达标即终止） | 50 | **84.6** |

**「永远差一点」拿 304.9 分，「完全达标」只拿 84.6 分 —— 差 3.6 倍。**

### 2.3 为什么这是必然的

每步存活奖励 +0.5。达标即终止 ⇒ 放弃之后每一步的存活奖励。
- 达标发生在第 50 步：赚 50 步 × 0.5 + 20 = 45 分（外加姿态奖励）
- 不达标活到第 414 步：赚 414 步 × 0.5 ≈ 305 分（外加姿态奖励）

**RL 是理性的，它精确地选择了次优解：卡在达标前一步，永远不达标、永远不坠地。**

这解释了此前所有看似矛盾的现象：
- 稳态油门 0.49 < 悬停 0.7075 → 少出力可以延长存活
- 每帧 0/1 全幅翻转 → 二值振荡是「维持平均推力 + 避免达标」的最优解
- ω=5 也是 0/20 → 与 ω 无关，任何状态都选择不达标
- 完美初态只保持 8 步 → 主动从完美态掉出来，因为达标就结束
- pd_sweep 里 P2 平均油门 0.238 → 学会了「少出力、活更久」

### 2.4 结构性旁证：端到端为什么没这个病

`phase=0` 分支里 `terminated` **恒为 False**，只有坠地/出界才结束回合。
没有任何「达标即终止」的漏洞 —— 这正是 E-A2 能到 61.1% 而 P2 恒 0% 的结构性原因。

## 3. 修复（v19）

### 3.1 改动

```python
# v19：+20 只发一次，达标后【不终止回合】
if self._stable_steps >= 50 and not self._success_paid:
    reward += 20.0
    self._success_paid = True
terminated = False
```

配套：`reset()` 里必须复位 `_stable_steps` 与 `_success_paid`。
否则 +20 只会在进程内第一回合发放 —— 这与 v8 History Stacking 漏清 `_hist`
是同一类跨回合状态泄漏 bug，已一并修正。

### 3.2 修复后的回报账本（实测）

| 油门 u | 推力/重力 | 存活步 | 最长达标 | 累计回报 |
|---|---|---|---|---|
| 0.50 | 0.50 | 219 | 13 | 10.3 |
| 0.60 | 0.72 | 299 | 17 | 132.0 |
| 0.65 | 0.84 | 414 | 25 | 304.9 |
| 0.70 | 0.98 | 800 | 800 | **1084.9** |
| 0.7075（悬停） | 1.00 | 800 | 800 | **1160.8** |
| 0.72 | 1.04 | 800 | 569 | 1052.4 |

**梯度方向正确：满分 1160.8 > 差一点 304.9，比值 3.8（修复前是 0.28）。**
u=0.72 推力过剩反而下降（爬升出界 + 姿态难稳），说明最优解被正确锁在 0.70~0.71。

## 4. 元规则补充（写进 实验总览.md）

第 17 条：**改判据/改终止条件前，必须先算一遍「一个理性策略能拿到的最大回报是多少」。**
方法：构造 3~5 个恒定动作基线策略（如恒定油门），跑满回合算累计回报。
若最优基线策略不是「达标策略」，说明奖励账本倒挂，此时任何训练都不会收敛到目标。

第 18 条：**判据可达性必须扫描控制器强度，不能用单点测量下结论。**
本次教训：单点 kp=0.020 得出「物理不可达」，扫描后发现 kp=0.010 就有 54%。
单点测量只能证明「某个控制器不行」，不能证明「任务不可达」。

第 19 条：**归因前先排除「与变量无关的常数失败」。**
若某策略在变量取极小值（如 ω_tilt=5）时仍 100% 失败，说明失败与该变量无关，
应立刻转向找那个「恒定的共性病因」，而不是继续在变量轴上找规律。
